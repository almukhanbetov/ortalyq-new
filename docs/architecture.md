# Архитектура ORTALYQ-NEW

## Сущности БД

| Область | Таблицы |
|---|---|
| Пользователи и доступ | `users` (роль admin/teacher/student, locale, timezone), `sessions` (только SHA-256 токена), `login_attempts`, `teacher_students` |
| Классы | `classrooms` (`current_lesson_id`), `classroom_members` (роль в классе), `classroom_courses` (доступ курсов классу) |
| Шаблоны | `courses → lessons` (параметры материала: язык, возраст, уровень, тип, навыки, время, грамматика, лексика, функции, теги) `→ sections` |
| Упражнения | `exercises` (scope lesson/homework, section, hidden, current_version) → `exercise_versions` (заголовок и настройки) → `exercise_questions` → `exercise_options`; `score_categories` |
| Прохождение | `classroom_lessons` (открыт, завершён, оценка), `classroom_lesson_events` (аудит), `section_completions`, `attempts` (версия, `deadline_at`, статус in_progress/finished/reset, итоги), `attempt_answers` |
| Домашняя работа | `homeworks` (класс + урок + ученик → статус), `homework_submissions` (неизменяемые снимки JSON), `homework_status_events` (кто, когда, из какого статуса в какой) |
| Чат | `chat_messages` (уникальность `(author_id, client_id)`), `attachments` |
| Марафоны | класс с `lesson_type='marathon'` + `marathon_settings` (направление, язык, часовой пояс владельца, режим); `classrooms.archived_at` — «удалённый» марафон скрыт для всех, история сохраняется |

Ключевые ограничения:
- частичный уникальный индекс `attempts_live_uq` — одна «живая» попытка на класс, упражнение и ученика;
- `CHECK ((completed_at IS NULL) = (grade IS NULL))` на `classroom_lessons`;
- `UNIQUE (classroom_id, lesson_id, student_id)` на `homeworks`;
- внешние ключи с `ON DELETE` — по смыслу связи.

## Статусы домашней работы

```
not_submitted ──(ученик отправил)──▶ pending ──(преподаватель: «Завершить»)──▶ done
      ▲                               │  ▲                                        │
      │                 («На доработку»)  │(ученик отправил повторно)             │
      │                               ▼  │                                        │
      └──────────(«Изменить статус»)── revision ◀──────(«Изменить статус»)────────┘
not_submitted ──(преподаватель завершает до отправки, после подтверждения)──▶ done
```

- Каждая отправка создаёт новый снимок. Черновик на доработке снимки не меняет.
- `pending`/`done` блокируют ответы на сервере (`409 homework_locked`).
- `revision`/`not_submitted` снова открывают попытки; ответы, мгновенно проверенные как неверные, становятся редактируемыми.
- Завершённость работы и правильность ответов хранятся раздельно. Зелёный статус не означает «всё верно»: у ответов есть собственные отметки «Верно»/«Неверно» с иконкой.

## Проверка ответов и раскрытие ключа

| Режим | До завершения | После завершения |
|---|---|---|
| `instant` | одиночный выбор проверяется при выборе, множественный — кнопкой «Проверить». Проверенный ответ фиксируется; ключ раскрывается только для проверенного вопроса | всё раскрыто |
| `after` | нейтральное выделение, ключа нет | всё раскрыто |

Преподаватель видит ключ всегда, а ответы ученика — только для просмотра: варианты в его режиме не являются кнопками.

## Таймер

`deadline_at = now() + timer_seconds` записывается при старте. Повторный старт идемпотентен и возвращает тот же срок. Ответ после срока отклоняется (`409 attempt_expired`). При любом чтении просроченная попытка завершается с `finish_reason=timeout` и `finished_at = deadline_at`. Клиент показывает отсчёт с поправкой на расхождение часов (`server_now`) и по нулю вызывает `finish`.

## Realtime

`GET /api/classrooms/:id/ws`: сначала проверяются cookie сессии и членство в классе (иначе 401/404), затем Origin из `CORS_ORIGINS`. События:

| Тип | Содержимое |
|---|---|
| `chat.message.created` / `chat.message.updated` | сообщение целиком (видно всем участникам) |
| `chat.message.deleted` | `{id}` |
| `homework.status_changed` | `{lesson_id, student_id, status}` |
| `lesson.completion_changed`, `section.completion_changed` | идентификаторы и флаг |
| `attempt.updated` | `{exercise_id, student_id, status}` — без ответов |
| `classroom.lesson_changed`, `materials.changed` | идентификаторы |
| `ping` | каждые 25 с, для клиентского сторожевого таймера |

Клиент: экспоненциальный backoff, закрытие сокета по событию `offline`, сторожевой таймер 60 с. После переподключения перечитываются класс, прогресс, упражнения, ДЗ и чат. Дубли сообщений исключаются по `id` и `client_id`.

**Индикаторы доставки:** «Отправляется…» — запрос в пути; «Не отправлено» + «Повторить» — запрос завершился ошибкой (повтор с тем же `client_id` не создаёт дубль). После ответа сервера сообщение выглядит обычным. Отметки «прочитано» нет, потому что нет подтверждающего события.

## Безопасность

- bcrypt (cost 12). Сессия — случайный токен 256 бит в cookie `HttpOnly; SameSite=Lax; Secure` (в production обязательно). В БД хранится только SHA-256 токена. Срок продлевается при активности.
- Ограничение входа: 5 неудачных попыток на email и 30 на IP за 15 минут → `429`.
- CSRF: `SameSite=Lax` плюс отклонение изменяющих запросов с чужим `Origin`.
- Отключение пользователя, смена роли или пароля завершает все его сессии.
- Все SQL-запросы параметризованы. Списки пагинируются (`limit/offset`, лимиты сверху).
